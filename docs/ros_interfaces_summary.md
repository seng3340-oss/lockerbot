# ROS 2 인터페이스 쉽게 보기

인터페이스는 각 노드가 주고받을 데이터의 양식이다. 현재 구성은 **메시지 타입 8종, 서비스 5종, 액션 4종**이다. 메시지 타입 수가 토픽 수를 뜻하지는 않는다. 실제 기본 토픽 연결은 표준 카메라 영상까지 포함해 **4개**다.

현재는 인터페이스 정의와 빌드 설정까지 구현했다. 아래 내용은 후속 노드가 따라야 할 통신 규약이며, 실제 발행·구독 노드, 서비스·액션 서버, SQLite 어댑터는 아직 연결하지 않았다. 상세 필드·엔드포인트·QoS·오류·검증 규칙과 빌드 방법은 [인터페이스 상세 문서](ros_interfaces.md)를 참고한다.

## 토픽은 계속 전달하는 정보

토픽은 오디오, 영상, 화면 안내처럼 정보를 계속 보내는 데 사용한다.

| 토픽 이름 | 보내는 쪽 → 받는 쪽 | 전달하는 데이터 |
| --- | --- | --- |
| `/lockerbot/audio` | 태블릿 인터페이스 → 대화 노드 | 마이크 오디오, 장비·세션 ID, 오디오 순번 |
| `/lockerbot/tablet_state` | 작업관리 → 태블릿 인터페이스 | 화면 모드, 인증 상태, 안내 문장, 음성 출력 여부, 진행률 |
| `/lockerbot/dialogue_context` | 작업관리 → 대화 노드 | 현재 질문, 예상 응답 종류, 선택 가능한 물품, 응답 만료 시각 |
| `/lockerbot/camera/image_raw` | 인식 → 태블릿 인터페이스 | 카메라 영상. ROS 표준 `sensor_msgs/msg/Image` 타입 사용 |

여기서 태블릿 인터페이스는 Android 태블릿과 ROS 사이를 연결하는 노드다. 태블릿과의 WSS/HTTPS 연결은 별도 구현 대상이다.

## 직접 만든 메시지 타입 8종

`AudioChunk`, `TabletState`, `DialogueContext`는 위 토픽에 사용한다. 나머지 다섯 타입은 서비스·액션 안에서 공통 데이터로 사용한다.

| 메시지 이름 | 쉬운 의미 | 들어 있는 데이터 |
| --- | --- | --- |
| `AudioChunk` | 마이크 음성 한 조각 | 녹음 시각, 장비·세션·스트림 ID, 순번, 샘플링 주파수, 채널 수, 음성 데이터 |
| `TabletState` | 태블릿에 보여줄 내용 | 시각, 장비·세션·화면 이벤트 ID, 화면 모드, 인증 상태, 카메라 켜기 여부, 사용자 ID·이름, 안내 문장, 음성 출력 여부, 진행률, 세션 정리 여부 |
| `DialogueContext` | 지금 사용자에게 묻고 있는 질문 | 시각, 세션·작업·질문 ID, 질문 종류, 질문 문장, 작업 계획, 선택 가능한 물품 ID, 만료 시각 |
| `DetectedItem` | 카메라에서 발견한 물품 | 관측 ID, 연결된 물품 ID, 물품 종류, 인식 신뢰도, 집을 위치·자세, 자세 유효 여부·기한, 가림 여부 |
| `ItemState` | DB에 기록된 물품의 현재 상태 | 물품 ID, 소유자, 이름·종류, 현재 상태·위치, 갱신 시각, 마지막으로 확실히 확인한 상태·위치·시각 |
| `ItemResult` | 물품 하나를 처리한 결과 | 이벤트·사용자·물품 ID, 보관/반환 구분, 성공/실패/위치 불명, 목적 위치, 발생 시각, 작업 전 갱신 시각, 실패 사유 |
| `AttendanceEvent` | 확정된 출입 기록 | 이벤트 ID, 사용자 ID, 출근/외출/복귀/퇴근 구분, 발생 시각 |
| `OperationStatus` | 공통 성공·실패 정보 | 성공 여부, 오류 코드, 설명 문장 |

`ItemState`의 상태는 다음 네 가지다.

| 상태 | 의미 |
| --- | --- |
| `WITH_USER` | 사용자 보유를 확인한 상태 |
| `STORED` | 지정된 보관 위치에 놓았음을 확인한 상태 |
| `ON_TRAY` | 트레이에 반환했음을 확인한 상태. 사용자가 가져갔다는 뜻은 아님 |
| `UNKNOWN` | 현재 위치나 상태를 확정할 수 없음 |

`DetectedItem`의 관측 ID는 영상에서 발견한 대상을 가리키고, 물품 ID는 DB에 등록된 개별 실물을 가리킨다. 예를 들어 검출 라벨이 같은 차키 두 개도 물품 ID는 서로 달라야 한다.

## 서비스 5개: 요청하고 응답을 한 번 받기

서비스는 **Request(요청) → Response(응답)** 구조다.

| 서비스 이름 | 누가 누구에게 | 보내는 요청 | 받는 응답 |
| --- | --- | --- | --- |
| `StartSession` | 대화 → 작업관리 | 요청 ID, 태블릿 ID, 감지한 호출어, 감지 시각 | 접수 결과, 발급된 세션 ID, 세션 만료 시각 |
| `SubmitAnswer` | 대화 → 작업관리 | 요청·세션·작업·질문 ID, 예/아니요·물품 선택·자유 응답 구분, 인식 문장, 선택한 물품 ID, 응답 시각 | 답변 접수 성공 여부와 사유 |
| `GetItems` | 작업관리 → 저장 어댑터 | 사용자 ID, 보관 중인 물품만 조회할지 여부 | 조회 결과와 물품 상태 목록 `ItemState[]` |
| `RecordAttendance` | 작업관리 → 저장 어댑터 | 확정된 출입 기록 `AttendanceEvent` | 저장 성공 여부와 사유 |
| `RecordItemResult` | 작업관리 → 저장 어댑터 | 물품 하나의 처리 결과 `ItemResult` | 저장 성공 여부와 사유 |

예를 들어 “Hello ROKEY”를 감지하면 `StartSession`으로 대화를 시작한다. “출입증과 소지품을 보관할까요?”에 사용자가 “네”라고 답하면 `SubmitAnswer`로 해당 질문에 대한 응답을 전달한다. 세션 시작 성공은 얼굴 인증 성공을 뜻하지 않고, 답변 접수 성공도 물리 작업 성공을 뜻하지 않는다.

`RecordItemResult` 응답이 성공이면 전달한 결과를 DB에 저장했다는 뜻이다. 전달한 내용이 “위치 불명”이었다면 물리 작업까지 성공했다는 뜻은 아니다. 물리 결과는 `ItemResult.outcome`의 SUCCESS(성공), FAILED_UNCHANGED(이동하지 않았음을 확인한 실패), UNKNOWN(위치 불명)으로 구분한다.

## 액션 4개: 작업 요청, 진행 상황, 최종 결과

액션은 **Goal(수행할 작업)을 보내고 → Feedback(진행 상황)을 여러 번 받다가 → Result(최종 결과)를 한 번 받는 구조**다. 파일 안의 선언 순서는 Goal / Result / Feedback이며, 실행 중 주고받는 순서와 구분한다.

### 1. ExecuteTask — 출근·복귀·외출·퇴근 업무 전체 실행

대화 노드 → 작업관리 노드.

- **Goal:** 세션·작업 ID, 업무 종류, 사용자 요청 문장, 반환할 물품의 포함·제외 목록, 외출 시 출입증 반환 여부, 제한 시간.
- **Feedback:** 작업 ID, 현재 단계, 진행률, 처리 중인 물품, 완료한 물품 수, 전체 물품 수, 안내 문장.
- **Result:** 전체 성공·실패, 작업 ID, 인증된 사용자 ID, 물품별 처리 결과, 완료하지 못한 물품 목록.

예: “퇴근할게요. 차키와 출입증을 돌려주세요.”

업무 종류는 `CHECK_IN`(출근), `RETURN`(복귀), `GO_OUT`(외출), `CHECK_OUT`(퇴근)이다. 사용자 ID는 요청자가 주장하는 값 대신 작업관리자가 인증한 세션에서 얻는다. 퇴근 시 출입증 반환은 필수다.

### 2. IdentifyUser — 얼굴 또는 출입증 소유자 확인

작업관리 노드 → 인식 노드.

- **Goal:** 세션 ID, 얼굴 확인/출입증 소유자 확인 구분, 제한 시간.
- **Feedback:** 인식 단계, 진행률, 안내 문장.
- **Result:** 판독 성공·실패, 확인된 사용자 ID·이름, 인식 신뢰도, 관측 시각.

모드는 `FACE`(얼굴 확인), `BADGE_OWNER`(출입증 소유자 확인)다. 얼굴과 출입증에서 나온 사용자 ID가 같은지는 작업관리자가 비교한다.

### 3. DetectItems — 물품 탐색과 집기 위치 확인

작업관리 노드 → 인식 노드.

- **Goal:** 세션·작업 ID, 카드 집기 위치 확인/트레이 전체 스캔/특정 물품 찾기 구분, 탐색 위치, 대상 물품 ID, 제한 시간.
- **Feedback:** 탐색 단계, 진행률, 발견한 물품 수, 안내 문장.
- **Result:** 탐색 성공·실패, 발견한 물품 목록과 집기 위치·자세, 가림 여부, 찾지 못한 물품 ID.

예: “트레이를 스캔해줘”, “서랍에서 이 차키를 찾아줘.”

모드는 `BADGE_GRASP`(카드 집기 자세), `SCAN_TRAY`(트레이 스캔), `FIND_ITEMS`(지정 물품 찾기)다. 정상 관측에서 트레이가 비어 있으면 성공과 빈 목록을 반환한다.

### 4. ExecuteRobotStep — 로봇 동작 한 단계 실행

작업관리 노드 → 로봇 실행 노드.

- **Goal:** 세션·작업·단계 ID, 수행할 동작, 지정 자세 이름, 사용자·물품 ID, 출발·목적 위치, 집기·놓기 자세, 관측 유효 기한, 결과 기록용 이벤트 ID, 작업 전 갱신 시각, 제한 시간.
- **Feedback:** 단계 ID, 현재 실행 단계, 진행률, 안내 문장.
- **Result:** 동작 성공·실패, 확인 가능한 경우 도달한 자세, 보관·반환을 시도했다면 해당 물품의 처리 결과. 자세와 물품 결과에는 각각 유효 여부를 나타내는 값이 함께 들어간다.

수행할 동작은 다음과 같다. 동작에 필요한 필드만 채운다.

| 동작 이름 | 의미 |
| --- | --- |
| `MOVE_NAMED_POSE` | 지정된 대기·관측 자세로 이동 |
| `OPEN_DRAWER` | 서랍 열기 |
| `CLOSE_DRAWER` | 서랍 닫기 |
| `STORE_ITEM` | 물품 보관 |
| `RETURN_ITEM` | 물품을 트레이에 반환 |
| `TEMP_MOVE_ITEM` | 가리는 물품을 임시 위치로 이동 |
| `RESTORE_ITEM` | 임시 이동한 물품을 원래 위치로 복구 |

취소나 전체 실패가 발생해도 이미 완료된 개별 물품 결과는 보존한다. 취소했다는 이유로 물건이 원래 위치로 돌아갔다고 추정하지 않는다.
